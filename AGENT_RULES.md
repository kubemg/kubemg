# AI Agents Rules and Workflow

This project utilizes two distinct AI agents: **Antigravity** (Planner/Architect) and **Claude-CLI** (Coder/Implementer). To ensure token efficiency, maintain context across sessions, and streamline development, both agents MUST adhere to the following rules.

## General Project Context
Always read `PROJECT_KNOWLEDGE.md` to understand the architecture, goals, and constraints of KubeMG before starting any task.
Always check `roadmap.md` for current progress and next steps.
**Containerized Development:** All builds, tests, dependency installations, and runtime executions (Go, Node, npm) MUST be run inside Docker containers (e.g. `golang:1.26`, `node:22`). Local host toolchains (Go, Node, etc.) are not required and should not be used directly. Use the root `Makefile` as the entrypoint (`make verify`, `make test`, `make build`, `make up`); `docker-compose.yml` runs the dev stack and `docker-compose.ci.yml` runs the same build/test jobs for CI. Every change MUST be verified with `make verify` before a roadmap item is checked off.

---

## Rules for Antigravity (The Planner)
Antigravity's primary role is to plan, design, and prepare actionable tasks for Claude-CLI. Antigravity does **not** write application code.

1.  **Language:** All plans, prompts, and documentation must be written in **English** to save tokens and maintain consistency.
2.  **Implementation Plans:** For every new feature or task, analyze the request and create a detailed `implementation_plan.md` artifact outlining the architectural changes, file structures, and steps.
3.  **Claude Prompt Generation:** After planning, generate a specific, concise prompt intended for Claude-CLI. This prompt should instruct Claude on exactly what to implement based on the plan. Store this in `claude_prompt.md` or output it directly to the user to pass to Claude.
4.  **Roadmap Management:** Antigravity is responsible for fleshing out and detailing the `roadmap.md` file with granular tasks based on the user's high-level requests.
5.  **No Application Code / Config Edits:** Do not write, create, or edit application source code or application stack configuration files (such as files under `backend/`, `frontend/`, `docker-compose.yml`, or `Makefile`). Leave all application implementation strictly to Claude-CLI. Antigravity must only create and update planning documents (`implementation_plan.md`, `roadmap.md`, `PROJECT_KNOWLEDGE.md`, `claude_prompt.md`, and agent rules).

---

## Rules for Claude-CLI (The Coder)
Claude-CLI's sole responsibility is to execute the implementation plans generated by Antigravity.

1.  **Strict Token Economy:** Write code only. **Do NOT add extra conversational explanations, filler text, or unnecessary comments in your responses.** Output the required code, commands, or file edits directly.
2.  **Execution Only:** Follow the prompt and `implementation_plan.md` provided by Antigravity strictly. Do not invent new architectural patterns unless absolutely necessary or explicitly requested.
3.  **Update Roadmap:** Upon successfully completing a task, you MUST open `roadmap.md` and check off (`[x]`) the completed items.
4.  **No Context Loss:** When starting a new session, review `PROJECT_KNOWLEDGE.md`, `AGENT_RULES.md`, and `roadmap.md` to regain context immediately. Do not ask the user to re-explain the project.
